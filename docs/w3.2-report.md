# W3.2 — blocking CI gate + parser fixes

Date: 2026-11-14 · Branch `feat/w3` · Status: implemented and published as
`v0.1.0-alpha` (no outreach).

## 1. GitHub workflow (item 1)

`.github/workflows/skill-ci.yml` now has two jobs and a reusable entry:

- **`example-gate` (blocking)** — lints `examples/skills`, a small valid
  skill set; a real error fails the job. This is the "CI can gate"
  demonstration that W3.1 lacked.
- **`fixture-smoke` (non-blocking)** — still lints the repo's own
  `tests/fixtures` tree, which intentionally contains malformed skills;
  `continue-on-error: true` is retained and documented.
- **`workflow_call`** — accepts a `target` input (default
  `examples/skills`), so another repository can call this workflow and
  run a blocking gate against its own skills.

`examples/skills/example-skill/SKILL.md` is a minimal valid skill; the
example gate exits 0 on it.

Local validation: `python -m skill_ci examples/skills` → exit 0, one
skill, zero findings. First push validated the workflow: both the `main`
and `feat/w3` runs completed successfully, and the blocking example gate
is green.

## 2. Parser fixes (item 2)

Two valid-YAML constructs that produced FM001 in W3.1 are now parsed:

1. **`/` in nested-map keys** — e.g.
   `metadata:\n  opencode/autoinvoke: false`. `_KEY_RE` now allows
   `[A-Za-z0-9_./-]` in keys; the subkey is stored as a plain string and
   no FM001/FM007 is emitted for it (rules still decide whether a nested
   subkey matters).
2. **Block scalars as nested-map entry values** — e.g.
   `metadata:\n  changelog: >-\n    line1\n    line2` and
   `literal: |-`. A new `_consume_nested_block_scalar` consumes indented
   content, folds `>` to spaces and keeps newlines for `|`, and applies
   approximate chomping (`-` strips, `+` keeps one trailing newline).

`FM008` (info, depth-2+ nested mapping stored raw) is unchanged: genuine
two-level maps are still captured raw and reported as info, never
FM001.
